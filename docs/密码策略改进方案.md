# 密码策略配置建议

## 方案一：统一密码（适合简单场景）

### 使用场景
- 所有外部系统密码策略一致
- 用户数量少，管理简单
- 内部系统，安全要求不高

### 实现方式
1. 在"用户管理"中添加用户时设置密码
2. 密码存储在 auth_users 表的 password 字段
3. 分配角色时使用这个统一密码

### 数据库改进
```sql
ALTER TABLE auth_users ADD COLUMN password VARCHAR(100) COMMENT '统一初始密码（加密存储）';
ALTER TABLE auth_users ADD COLUMN password_encrypted TINYINT(1) DEFAULT 0 COMMENT '密码是否已加密';
```

### API改进
- 添加用户时增加密码输入框
- 密码加密存储（使用 bcrypt 或 AES）
- 分配角色时解密并使用

---

## 方案二：独立密码（当前方案，适合复杂场景）

### 使用场景
- 不同系统有不同密码策略
- 高安全要求的环境
- 需要细粒度权限控制

### 实现方式
1. 添加用户时不设置密码
2. 分配角色时为每个系统生成独立密码
3. 密码不存储，只在创建时显示一次

---

## 方案三：应用级密码策略（推荐）

### 设计思路
每个外部应用配置自己的密码策略：

```json
{
  "appName": "Jenkins",
  "passwordPolicy": {
    "length": 12,
    "upperCount": 2,
    "lowerCount": 4,
    "digitCount": 4,
    "specialChars": "@#$%",
    "specialCount": 2
  }
}
```

### 数据库改进
```sql
ALTER TABLE applications ADD COLUMN password_policy JSON COMMENT '密码生成策略';
```

### 优点
- 每个应用独立配置密码策略
- 自动生成符合要求的密码
- 灵活适应不同系统
- 可选是否保存到 auth_users

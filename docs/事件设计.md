## 🎯 设计目标

设计一个完善的系统事件通知机制，用于记录和通知系统中发生的各种重要事件，与现有的告警系统形成互补关系。

## 📊 事件通知 vs 告警通知的区别

### 🚨 告警通知

**特点**：
- **紧急性**: 需要立即处理的问题
- **阈值触发**: 基于预设阈值自动触发
- **技术导向**: 系统异常、性能问题、安全风险
- **需确认**: 通常需要人工确认和处理
- **持续状态**: 有产生、持续、解决的生命周期

**示例**：
- CPU使用率超过90%
- 磁盘空间不足
- 服务宕机
- 网络连接异常

### 🔔 事件通知

**特点**：
- **信息性**: 记录系统发生的重要事件
- **业务导向**: 用户操作、状态变更、业务流程节点
- **即时通知**: 事件发生时立即通知
- **无需处理**: 主要是告知性质，不需要立即响应
- **历史记录**: 形成系统事件时间线

**示例**：
- 用户登录/登出
- 配置变更
- 任务执行完成
- 部署成功/失败
- 定期维护提醒

## 🗄️ 数据库设计

### 1. 系统事件表

```sql
-- 系统事件表
CREATE TABLE IF NOT EXISTS system_events (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    event_type VARCHAR(50) NOT NULL COMMENT '事件类型',
    event_category VARCHAR(30) NOT NULL COMMENT '事件分类: auth/deploy/task/config/maintenance',
    title VARCHAR(200) NOT NULL COMMENT '事件标题',
    content TEXT COMMENT '事件内容详情',
    level VARCHAR(20) DEFAULT 'info' COMMENT '事件级别: info/success/warning/error',
    source_type VARCHAR(30) NOT NULL COMMENT '来源类型: user/system/agent/k8s',
    source_id VARCHAR(100) COMMENT '来源ID',
    operator_id INT UNSIGNED COMMENT '操作者ID',
    operator_name VARCHAR(100) COMMENT '操作者名称',
    target_type VARCHAR(50) COMMENT '目标类型: server/deployment/config等',
    target_id VARCHAR(100) COMMENT '目标ID',
    target_name VARCHAR(200) COMMENT '目标名称',
    metadata JSON COMMENT '额外元数据',
    is_read BOOLEAN DEFAULT FALSE COMMENT '是否已读',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    expire_at DATETIME COMMENT '过期时间',
    
    INDEX idx_type_category (event_type, event_category),
    INDEX idx_level_read (level, is_read),
    INDEX idx_created_at (created_at),
    INDEX idx_operator (operator_id),
    INDEX idx_source (source_type, source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统事件表';
```

## 🔧 后端实现

### 1. 事件服务

```go
// backend/services/event_service.go
package services

import (
    "encoding/json"
    "time"
    "oneops/backend/models"
    "oneops/backend/logger"
    "go.uber.org/zap"
)

type EventService struct {
    db  *gorm.DB
    hub *WebSocketHub
}

type SystemEvent struct {
    EventType      string                 `json:"eventType"`
    EventCategory  string                 `json:"eventCategory"`
    Title          string                 `json:"title"`
    Content        string                 `json:"content"`
    Level          string                 `json:"level"`
    SourceType     string                 `json:"sourceType"`
    SourceID       string                 `json:"sourceId"`
    OperatorID     uint                   `json:"operatorId"`
    OperatorName   string                 `json:"operatorName"`
    TargetType     string                 `json:"targetType"`
    TargetID       string                 `json:"targetId"`
    TargetName     string                 `json:"targetName"`
    Metadata       map[string]interface{} `json:"metadata"`
    ExpireDays     int                    `json:"expireDays"`
}

// PublishEvent 发布事件
func (s *EventService) PublishEvent(event *SystemEvent) error {
    // 1. 保存到数据库
    eventData := &models.SystemEvent{
        EventType:     event.EventType,
        EventCategory: event.EventCategory,
        Title:         event.Title,
        Content:       event.Content,
        Level:         event.Level,
        SourceType:    event.SourceType,
        SourceID:      event.SourceID,
        OperatorID:    event.OperatorID,
        OperatorName:  event.OperatorName,
        TargetType:    event.TargetType,
        TargetID:      event.TargetID,
        TargetName:    event.TargetName,
        IsRead:        false,
        CreatedAt:     time.Now(),
    }
    
    // 设置过期时间
    if event.ExpireDays > 0 {
        eventData.ExpireAt = time.Now().AddDate(0, 0, event.ExpireDays)
    }
    
    // 存储元数据
    if event.Metadata != nil {
        metadataJSON, _ := json.Marshal(event.Metadata)
        eventData.Metadata = string(metadataJSON)
    }
    
    if err := s.db.Create(eventData).Error; err != nil {
        logger.Error("保存系统事件失败", zap.Error(err))
        return err
    }
    
    // 2. 通过WebSocket推送给在线用户
    s.BroadcastEvent(eventData)
    
    // 3. 发送订阅通知（邮件、微信等）
    s.SendSubscribedNotifications(eventData)
    
    return nil
}

// BroadcastEvent 广播事件到WebSocket
func (s *EventService) BroadcastEvent(event *models.SystemEvent) {
    wsMessage := &WebSocketMessage{
        Type: "system_event",
        Data: event,
        Timestamp: time.Now().Format(time.RFC3339),
    }
    s.hub.Broadcast(wsMessage)
}

// SendSubscribedNotifications 发送订阅通知
func (s *EventService) SendSubscribedNotifications(event *models.SystemEvent) {
    // 查询订阅了该事件类型的用户
    var subscriptions []models.EventSubscription
    s.db.Where("enabled = ? AND JSON_CONTAINS(event_types, ?)", true, 
              fmt.Sprintf(`"%s"`, event.EventType)).Find(&subscriptions)
    
    for _, sub := range subscriptions {
        // 根据用户配置的通知渠道发送通知
        // 实现邮件、微信等通知逻辑
    }
}

// GetUserEvents 获取用户事件列表
func (s *EventService) GetUserEvents(userID uint, page, pageSize int, unreadOnly bool) ([]models.SystemEvent, int64, error) {
    var events []models.SystemEvent
    var total int64
    
    query := s.db.Model(&models.SystemEvent{})
    
    if unreadOnly {
        query = query.Where("is_read = ? OR is_read IS NULL", false)
    }
    
    query.Count(&total)
    query.Order("created_at DESC").
          Limit(pageSize).
          Offset((page - 1) * pageSize).
          Find(&events)
    
    return events, total, nil
}

// MarkEventAsRead 标记事件为已读
func (s *EventService) MarkEventAsRead(eventID uint, userID uint) error {
    return s.db.Model(&models.SystemEvent{}).
        Where("id = ?", eventID).
        Update("is_read", true).Error
}

// MarkAllAsRead 标记所有事件为已读
func (s *EventService) MarkAllAsRead(userID uint) error {
    return s.db.Model(&models.SystemEvent{}).
        Where("is_read = ? OR is_read IS NULL", false).
        Update("is_read", true).Error
}

// GetUnreadCount 获取未读事件数量
func (s *EventService) GetUnreadCount(userID uint) (int64, error) {
    var count int64
    s.db.Model(&models.SystemEvent{}).
        Where("is_read = ? OR is_read IS NULL", false).
        Count(&count)
    return count, nil
}
```

## 📋 设计要点总结

1. **明确区分**: 事件通知 ≠ 告警通知，各有定位和用途
2. **完整生命周期**: 事件产生 → 存储 → 推送 → 阅读 → 过期清理
3. **多维度分类**: 按类型、级别、来源进行分类管理和筛选
4. **灵活订阅**: 支持用户按需订阅不同类型的事件通知
5. **多渠道通知**: Web界面 + 邮件 + 微信等多渠道推送
6. **性能优化**: 
   - 合理的索引设计
   - 过期事件自动清理
   - 分页查询支持
   - WebSocket实时推送
7. **扩展性**: 易于添加新的事件类型和通知渠道

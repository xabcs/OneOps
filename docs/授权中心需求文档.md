# 授权中心需求文档

## 一、业务背景

### 1.1 问题现状

运维团队需要管理多个外部运维工具（Jenkins、Nacos、XXL-Job、RocketMQ 等），每个工具都有独立的用户权限体系。当有新员工入职或员工离职时，需要在多个系统中重复进行权限配置，工作繁琐且容易遗漏，造成安全隐患。

### 1.2 解决方案

建设统一的授权中心，实现：
- 集中管理外部系统的应用信息
- 统一管理用户在不同系统的角色权限
- 通过角色映射实现一次配置，多系统生效
- 全程操作可审计、可追溯

## 二、核心概念

### 2.1 名词定义

| 名词 | 说明 |
|------|------|
| **外部应用** | 第三方运维工具，如 Jenkins、Nacos、XXL-Job、RocketMQ 等 |
| **本地角色** | OneOps 系统中定义的角色，如"开发工程师"、"运维工程师"等 |
| **外部角色** | 外部应用中定义的角色，如 Jenkins 的 "Developer"、"Admin" 等 |
| **角色绑定** | 本地角色与外部应用角色的映射关系 |
| **用户授权** | 为用户分配本地角色，自动获得对应外部系统的权限 |

### 2.2 用户体系

- **OneOps 用户体系**：独立管理，用于登录 OneOps 平台
- **外部系统用户体系**：每个外部系统独立的用户管理
- **用户不互通**：OneOps 用户与外部系统用户是独立的，不进行同步

## 三、功能需求

### 3.1 外部应用管理

#### 3.1.1 功能描述

管理需要对接的外部应用信息，包括应用的基本信息、连接配置等。

#### 3.1.2 功能点

**应用列表**
- 展示所有已注册的外部应用
- 显示信息：应用名称、应用代码、应用类型、Base URL、状态、最后同步时间
- 支持按应用名称搜索
- 支持分页展示

**添加应用**
- 填写应用基本信息：
  - 应用名称（必填）
  - 应用代码（必填，唯一标识）
  - 应用类型（必填，下拉选择：Jenkins/Nacos/XXL-Job/RocketMQ/其他）
  - Base URL（必填，应用的访问地址）
  - 描述（选填）
  - 同步间隔（选填，默认60分钟）
- 配置API认证信息：
  - 认证方式（必填，API Token/Basic Auth/OAuth 2.0）
  - 根据认证方式填写相应凭据
- 配置API端点：
  - 创建用户端点（必填，默认：/api/users）
  - 获取用户列表端点（必填，默认：/api/users）
  - 获取单个用户端点（必填，默认：/api/users/{username}）
  - 获取角色列表端点（必填，默认：/api/roles）
  - 分配角色端点（必填，默认：/api/users/{username}/roles）
  - 撤销角色端点（必填，默认：/api/users/{username}/roles/{roleCode}）
  - 获取用户角色端点（选填，默认：/api/users/{username}/roles）

**编辑应用**
- 修改应用的基本信息

**删除应用**
- 删除不再使用的外部应用
- 删除前需确认该应用下无角色绑定关系

**同步角色**
- 从外部应用同步角色列表到本地
- 调用外部应用的 REST API 获取角色数据
- 同步成功后更新最后同步时间
- 支持单个应用手动触发同步

**同步用户**
- 从外部应用同步用户列表到本地（仅用于展示）
- 调用外部应用的 REST API 获取用户数据
- 同步成功后更新最后同步时间

#### 3.1.3 数据字段

```
Application {
  id: number;              // 应用ID
  name: string;            // 应用名称
  code: string;            // 应用代码
  type: string;            // 应用类型（jenkins/nacos/xxl-job/rocketmq/other）
  baseUrl: string;         // 应用访问地址
  description: string;     // 应用描述
  syncInterval: number;    // 同步间隔（分钟）
  lastSyncTime: string;    // 最后同步时间
  status: number;          // 状态（1=启用，0=禁用）
  createdAt: string;       // 创建时间
  updatedAt: string;       // 更新时间
}
```

### 3.2 角色绑定

#### 3.2.1 功能描述

建立本地角色与外部应用角色的映射关系。当用户被分配本地角色后，自动获得对应外部系统的权限。

#### 3.2.2 功能点

**角色选择**
- 下拉选择本地角色（从系统管理-角色管理中获取）
- 选择后显示该角色的所有外部角色绑定

**绑定列表**
- 展示选中角色的所有外部角色绑定
- 显示信息：应用名称、外部角色名称、外部角色代码、角色类型
- 支持删除绑定关系

**添加绑定**
- 选择外部应用
- 选择该应用的外部角色（从已同步的角色列表中选择）
- 创建本地角色与外部角色的绑定关系

**删除绑定**
- 删除角色的绑定关系
- 删除后，拥有该本地角色的用户将失去对应外部系统的权限

#### 3.2.3 数据字段

```
ApplicationRole {
  id: number;              // 外部角色ID
  appId: number;           // 应用ID
  roleCode: string;        // 外部角色代码
  roleName: string;        // 外部角色名称
  roleType: string;        // 角色类型
  syncTime: string;        // 同步时间
}

RoleBinding {
  id: number;              // 绑定ID
  roleId: number;          // 本地角色ID
  appId: number;           // 应用ID
  applicationRoleId: number; // 外部角色ID
  createdAt: string;       // 创建时间
}
```

### 3.3 用户授权

#### 3.3.1 功能描述

为 OneOps 用户分配本地角色，用户通过角色绑定自动获得外部系统的权限。

**方案A：主动创建用户模式**

当为用户分配本地角色时，系统会自动：
1. 检查用户是否在外部系统中存在
2. 如果不存在，则调用外部系统的创建用户API创建用户
3. 然后为用户分配相应的角色权限

此方案假设 OneOps 用户与外部系统用户使用相同的用户名进行关联。

#### 3.3.2 功能点

**用户选择**
- 下拉选择 OneOps 用户
- 显示用户名和昵称
- 选择后显示该用户的所有角色

**用户角色列表**
- 展示选中用户的所有角色
- 显示信息：角色名称、角色代码、授权人、授权时间
- 支持删除用户的某个角色

**分配角色**
- 选择要分配的角色（从本地角色列表中选择）
- 为用户添加该角色
- 系统自动执行以下操作：
  1. 查找该本地角色绑定的所有外部应用和外部角色
  2. 对于每个外部应用：
     a. 尝试在外部系统中创建用户（如果用户不存在，忽略创建失败）
     b. 调用外部系统的授权API，为用户分配外部角色
  3. 记录授权人和授权时间
  4. 记录操作日志

**授权流程示例**

假设用户 "zhangsan" 被分配本地角色 "开发工程师"：
1. 系统查询 "开发工程师" 角色的所有绑定关系
2. 发现绑定：Jenkins应用 → Developer角色
3. 系统调用 Jenkins API：
   - POST {jenkinsBaseUrl}/api/users (创建用户 zhangsan)
   - POST {jenkinsBaseUrl}/api/users/zhangsan/roles (分配 Developer 角色)
4. 保存用户角色记录到 OneOps 数据库
5. 记录操作日志

**删除角色**
- 删除用户的某个角色
- 删除后用户将失去该角色对应的外部系统权限
- 系统自动调用外部应用的 API 撤销权限

#### 3.3.3 数据字段

```
UserRole {
  id: number;              // 记录ID
  userId: number;          // 用户ID
  roleId: number;          // 角色ID
  grantedBy: string;       // 授权人
  grantedAt: string;       // 授权时间
}
```

### 3.4 操作日志

#### 3.4.1 功能描述

记录所有权限相关的操作，便于审计和追溯。

#### 3.4.2 功能点

**应用选择**
- 下拉选择要查看的应用
- 选择后显示该应用的所有操作日志

**日志列表**
- 展示选中应用的所有操作记录
- 显示信息：操作类型、操作目标、状态、操作人、操作时间
- 支持分页展示

**操作类型**
- 角色同步
- 用户同步
- 权限授权
- 权限撤销
- 应用创建
- 应用更新
- 应用删除

**状态标识**
- 成功（绿色标签）
- 失败（红色标签）
- 进行中（黄色标签）

#### 3.4.3 数据字段

```
ApplicationOperationLog {
  id: number;              // 日志ID
  appId: number;           // 应用ID
  operation: string;       // 操作类型
  target: string;          // 操作目标
  status: string;          // 状态（success/failed/pending）
  operator: string;        // 操作人
  createdAt: string;       // 操作时间
}
```

## 四、技术需求

### 4.1 API 集成

#### 4.1.1 外部应用 API 规范

每个外部应用需提供以下 REST API：

**创建用户**
```
POST {baseUrl}/api/users
Headers: Authorization: {token}, Content-Type: application/json
Body: { "username": "user1", "password": "password123" }
Response: { "code": 0, "message": "success" }
```

**获取用户列表**
```
GET {baseUrl}/api/users
Headers: Authorization: {token}
Response: [
  { username: "user1", displayName: "用户1", email: "user1@example.com", status: "active" }
]
```

**获取角色列表**
```
GET {baseUrl}/api/roles
Headers: Authorization: {token}
Response: [
  { roleCode: "developer", roleName: "开发者", roleType: "global" },
  { roleCode: "admin", roleName: "管理员", roleType: "global" }
]
```

**为用户授权**
```
POST {baseUrl}/api/users/{username}/roles
Headers: Authorization: {token}, Content-Type: application/json
Body: { "roleCode": "developer" }
Response: { "code": 0, "message": "success" }
```

**撤销用户权限**
```
DELETE {baseUrl}/api/users/{username}/roles/{roleCode}
Headers: Authorization: {token}
Response: { "code": 0, "message": "success" }
```

#### 4.1.2 认证方式

支持以下认证方式：
- Basic Auth（用户名+密码）
- API Token（令牌认证）
- OAuth 2.0（可选）

### 4.2 数据同步

#### 4.2.1 同步策略

- **手动同步**：管理员手动触发角色/用户同步
- **定时同步**：按配置的同步间隔自动同步（后续版本）
- **增量同步**：只同步变更的数据（后续版本）

#### 4.2.2 同步流程

```
1. 管理员点击"同步角色"
2. 系统调用外部应用的获取角色 API
3. 解析返回的角色数据
4. 更新本地数据库中的角色表
5. 更新应用的最后同步时间
6. 记录操作日志
```

### 4.3 权限控制

#### 4.3.0 API路由设计说明

为了避免与系统管理模块的路由冲突，授权中心使用专门的API路径：

**系统管理模块**（OneOps系统用户和角色）：
- `/api/system/users` - 系统登录用户管理
- `/api/system/roles` - 系统角色管理

**授权中心模块**（外部系统权限管理）：
- `/api/system/auth-users` - 授权中心用户管理
- `/api/system/auth-roles` - 授权中心角色管理
- `/api/system/applications` - 外部应用管理
- `/api/system/roles/:id/bindings` - 角色绑定管理
- `/api/system/users/:id/roles` - 用户授权管理
- `/api/system/applications/:id/operation-logs` - 操作日志

#### 4.3.1 功能权限

需要配置以下权限点：
- `auth:app:query` - 查看应用列表
- `auth:app:create` - 创建应用
- `auth:app:update` - 更新应用
- `auth:app:delete` - 删除应用
- `auth:user:query` - 查看授权中心用户
- `auth:user:create` - 创建授权中心用户
- `auth:user:update` - 更新授权中心用户
- `auth:user:delete` - 删除授权中心用户
- `auth:role:query` - 查看授权中心角色
- `auth:role:create` - 创建授权中心角色
- `auth:role:update` - 更新授权中心角色
- `auth:role:delete` - 删除授权中心角色
- `auth:binding:query` - 查看角色绑定
- `auth:binding:create` - 创建角色绑定
- `auth:binding:delete` - 删除角色绑定
- `auth:userauthorization:query` - 查看用户授权
- `auth:userauthorization:create` - 为用户授权
- `auth:userauthorization:delete` - 删除用户授权
- `auth:log:query` - 查看操作日志

#### 4.3.2 数据权限

- 用户只能查看自己有权限的应用数据
- 操作记录包含操作人信息，支持追溯

### 4.4 安全要求

#### 4.4.1 数据安全

- 敏感信息（API Token、密码）加密存储
- 传输过程使用 HTTPS
- API 调用需要身份验证

#### 4.4.2 操作审计

- 所有操作记录到操作日志
- 记录操作人、操作时间、操作内容
- 日志不可删除、不可修改

## 五、非功能需求

### 5.1 性能要求

- 页面加载时间 < 2秒
- API 响应时间 < 500ms
- 支持并发用户数 ≥ 100

### 5.2 可用性要求

- 系统可用性 ≥ 99.9%
- 数据备份：每日备份
- 故障恢复时间 < 1小时

### 5.3 兼容性要求

- 支持主流浏览器：Chrome、Firefox、Safari、Edge
- 响应式设计，支持 1366x768 以上分辨率

## 六、用户界面

### 6.1 页面布局

采用 Tab 页签布局，包含四个功能模块：
1. 外部应用
2. 角色绑定
3. 用户授权
4. 操作日志

### 6.2 交互设计

**列表页面**
- 支持搜索、筛选
- 支持分页（10/20/50/100 条/页）
- 表格支持列排序
- 操作按钮固定在右侧

**表单页面**
- 采用抽屉式弹出
- 必填项标记 *
- 提交前进行表单验证
- 保存成功后自动关闭

**删除操作**
- 二次确认提示
- 删除成功后刷新列表

## 七、系统约束

### 7.1 前置条件

- 已完成 OneOps 平台的基础搭建
- 系统管理模块已实现用户、角色管理
- 外部应用提供标准化的 REST API

### 7.2 依赖关系

- 依赖系统管理的用户数据
- 依赖系统管理的角色数据
- 依赖外部应用的 API 可用性

### 7.3 限制条件

- 外部应用必须提供 REST API 接口
- 用户在不同外部系统的用户名必须一致
- 角色授权基于用户名匹配，不支持用户ID映射

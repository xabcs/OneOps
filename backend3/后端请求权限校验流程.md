
# 后端请求权限校验流程

## 一、请求校验全流程

```
请求进入
  │
  ▼
Auth() 中间件 — JWT 认证
  ├── 解析 Bearer token
  ├── 提取 user_id, username → 存入 gin.Context
  └── 失败 → 401 Unauthorized
  │
  ▼
RequirePermissionFromDB() 中间件 — 权限校验
  │
  ├── 1. 从 context 获取 user_id
  │
  ├── 2. 获取路由: method = c.Request.Method
  │         path = c.FullPath()  (如 /api/system/users)
  │
  ├── 3. 查 sys_permissions 表
  │      SELECT * WHERE route_method = 'GET' AND route_path = '/api/system/users'
  │      │
  │      ├── 查到 → perm.Code = "system.user.list"
  │      │
  │      └── 查不到 → 放行 (c.Next())
  │           (未配置路由映射的接口不受权限控制)
  │
  ├── 4. HasPermission(userID, "system.user.list")
  │      │
  │      ├── GetUserRoles(userID)
  │      │     解析 user.RoleIDs (JSON) → 查 sys_roles
  │      │
  │      ├── IsAdmin(roles)?
  │      │     role.Code == "admin" → return true (直接放行)
  │      │
  │      └── 遍历角色，调 Casbin:
  │           enforcer.Enforce(role.Code, "system.user.list", "*")
  │           ├── 匹配策略 p, ops, system.user.list, * → 放行
  │           └── 无匹配 → 403 Forbidden
  │
  ▼
到达 Controller
```

## 二、Casbin Enforce 内部过程

`enforcer.Enforce("ops", "system.user.list", "*")` 内部执行：

```
1. 查 sys_casbin_rule 表，取出该角色的所有策略
   SELECT * FROM sys_casbin_rule WHERE v0 = 'ops'

   返回:
   p, ops, system.user.list,    *
   p, ops, system.user.create,  *
   p, ops, cmdb.server.list,    *
   ... (该角色的所有策略)

2. 用 casbin_model.conf 的 matcher 逐条匹配:

   请求: r = (ops, system.user.list, *)
   策略: p = (ops, system.user.list, *)

   matcher: g(r.sub, p.sub) && r.obj == p.obj && r.act == p.act
            g(ops, ops)     ✓          ✓              ✓
            → 匹配成功 → allow

3. 返回 true → 放行
```

无权限时：

```
enforcer.Enforce("viewer", "system.user.delete", "*")

1. 查 sys_casbin_rule WHERE v0 = 'viewer'
   返回:
   p, viewer, dashboard.view, *
   p, viewer, system.user.list, *

2. 逐条匹配 "system.user.delete":
   (viewer, dashboard.view, *)   → obj 不匹配
   (viewer, system.user.list, *) → obj 不匹配

3. 无匹配 → 返回 false → 403 Forbidden
```

## 三、核心数据表

### sys_permissions — 权限定义表

```
+-----+----------------------+---------+----------+--------+--------------+-------------------+--------+
| id  | code                 | module  | resource | action | route_method | route_path        | status |
+-----+----------------------+---------+----------+--------+--------------+-------------------+--------+
| 1   | system.user.list     | system  | user     | list   | GET          | /api/system/users | 1      |
| 2   | system.user.create   | system  | user     | create | POST         | /api/system/users | 1      |
| 3   | system.role.create   | system  | role     | create | POST         | /api/system/roles | 1      |
| ...  |                      |         |          |        |              |                   |        |
+-----+----------------------+---------+----------+--------+--------------+-------------------+--------+
```

- `code`：权限码，格式 `模块.资源.操作`，是 Casbin 策略的 obj
- `route_method` + `route_path`：路由映射，中间件通过它找到请求对应的权限码
- 启动时由 `SyncRoutePermissions` 从 Gin 已注册路由自动提取并填充

### sys_roles — 角色表

```
+----+------+----------+--------+
| id | code | name     | status |
+----+------+----------+--------+
| 1  | admin  | 超级管理员 | 1      |
| 2  | ops    | 运维工程师 | 1      |
| 3  | auditor | 审计员    | 1      |
| 4  | viewer  | 查看者    | 1      |
| 5  | user    | 普通用户  | 1      |
| 6  | test    | 测试角色  | 1      |
+----+------+----------+--------+
```

### sys_users — 用户表

```
+----+----------+----------+-------------------+
| id | username | password | role_ids          |
+----+----------+----------+-------------------+
| 1  | admin    | ...      | [1]               |
| 2  | zhang    | ...      | [2, 3]            |
+----+----------+----------+-------------------+
```

- `role_ids`：JSON 数组，存储用户拥有的角色 ID

### sys_role_permissions — 角色-权限关联表

```
+---------+---------------+
| role_id | permission_id |
+---------+---------------+
| 2       | 1             |
| 2       | 2             |
| 2       | 3             |
+---------+---------------+
```

- 管理页面操作的数据源
- 修改后需调用 `syncRoleToCasbin` 同步到 Casbin

### sys_casbin_rule — Casbin 策略表

```
+-----+-----+--------------------+-----+
| pty | v0  | v1                 | v2  |
+-----+-----+--------------------+-----+
| p   | ops | system.user.list   | *   |
| p   | ops | system.user.create | *   |
| p   | ops | cmdb.server.list   | *   |
| ... |     |                    |     |
+-----+-----+--------------------+-----+
```

- `pty = p`：策略类型
- `v0`：角色码（如 ops、viewer）
- `v1`：权限码（如 system.user.list）
- `v2`：操作（统一为 `*`）
- 启动时由 `syncAPIPermissions()` 从 `sys_role_permissions` 同步生成

## 四、数据表之间的关系

```
sys_users                    sys_roles                    sys_permissions
┌──────────┐                ┌──────────┐                 ┌──────────────────┐
│ id       │                │ id       │                 │ id               │
│ username │                │ code     │                 │ code (唯一)       │
│ role_ids │───JSON数组────→│ name     │                 │ route_method     │
└──────────┘                │ status   │                 │ route_path       │
                            └──────────┘                 └──────────────────┘
                                 ↑                              ↑
                                 │                              │
                          sys_role_permissions                   │
                          ┌──────────────────┐                   │
                          │ role_id     ─────┼───────────────────┘
                          │ permission_id ───┘
                          └──────────────────┘
                                 │
                                 │ 启动时同步 (syncAPIPermissions)
                                 ▼
                          sys_casbin_rule
                          ┌──────────────────────────────┐
                          │ pty │ v0(角色) │ v1(权限码) │ v2 │
                          │  p  │ ops     │ system...│ *  │
                          │  p  │ viewer  │ system...│ *  │
                          └──────────────────────────────┘
```

### 三张核心表的定位

| 表                   | 回答的问题           | 一句话定位                                                  |
| -------------------- | -------------------- | ----------------------------------------------------------- |
| sys_permissions      | 系统有哪些权限？     | 权限的**目录定义表**，定义权限码及其路由映射          |
| sys_role_permissions | 角色被分配了什么？   | 角色-权限的**关联表**，管理页面操作的数据源           |
| sys_casbin_rule      | 这个请求能不能通过？ | Casbin 引擎的**运行时策略表**，权限校验的最终裁决依据 |

三者的协作关系：

```
管理页面勾选权限
       │
       ▼
sys_role_permissions              sys_permissions
"ops 角色有 id=1 的权限"  ──→  "id=1 是 system.user.list"
       │                                    │
       │ syncRoleToCasbin                   │
       ▼                                    ▼
sys_casbin_rule
"p, ops, system.user.list, *"
       │
       │ 请求到来时
       ▼
enforcer.Enforce("ops", "system.user.list", "*") → true
```

| 维度       | sys_permissions                  | sys_role_permissions           | sys_casbin_rule              |
| ---------- | -------------------------------- | ------------------------------ | ---------------------------- |
| 用途       | 定义权限码 + 路由映射            | 记录角色-权限分配关系          | Casbin 运行时策略            |
| 数据格式   | code + route_method + route_path | role_id + permission_id        | 角色码 + 权限码 (扁平字符串) |
| 谁写入     | seed 数据 + 管理页面             | 管理页面勾选                   | syncRoleToCasbin 自动同步    |
| 谁读取     | 中间件 + RBACService + 页面      | syncRoleToCasbin + RBACService | Casbin Enforce               |
| 能否手动改 | 能（管理页面）                   | 能（管理页面）                 | 不建议手动改（会被同步覆盖） |
| 删了会怎样 | 中间件找不到权限码               | 管理页面看不到分配关系         | Casbin 校验全部失效          |

## 五、启动初始化流程

```
main.go 启动
  │
  ├── initializer.Initialize()
  │    ├── 建表 (sys_users, sys_roles, sys_permissions, sys_role_permissions, sys_casbin_rule)
  │    ├── syncMenus()              — 菜单数据
  │    ├── syncBuiltinRoles()       — 6 个内置角色
  │    ├── syncUsers()              — admin 用户
  │    ├── syncPermissions()        — 129 个权限码（route_method/route_path 初始为空）
  │    ├── syncDefaultPermissions() — 为角色分配权限 → 写入 sys_role_permissions
  │    └── syncAPIPermissions()     — 同步到 Casbin → 写入 sys_casbin_rule
  │         └── 遍历每个角色:
  │              enforcer.AddPolicy(role.Code, perm.Code, "*")
  │
  ├── routes.SetupRoutes(r)
  │    └── 注册所有 Gin 路由 + 挂载中间件
  │
  └── SyncRoutePermissions(r)       — 从 Gin 路由自动提取 route_method/route_path
       ├── 遍历 engine.Routes()
       ├── 跳过公共路由 (login, heartbeat, ws)
       ├── 查 override 表 (特殊路由 → 权限码)
       ├── 约定推导 (GET→list, POST→create, PUT→update, DELETE→delete)
       └── 只更新 route_method/route_path 为空的权限（不覆盖管理页面手动配置）
```

## 六、路由映射自动推导规则

### 约定推导 (derivePermissionCode)

```
路由路径去掉 /api/ 前缀后拆分:

GET    /api/system/users         → module=system, resource=user, action=list   → system.user.list
POST   /api/system/users         → module=system, resource=user, action=create → system.user.create
PUT    /api/system/users/:id     → module=system, resource=user, action=update → system.user.update
DELETE /api/system/users/:id     → module=system, resource=user, action=delete → system.user.delete
GET    /api/system/users/:id     → module=system, resource=user, action=view   → system.user.view
```

### override 表 (routePermOverride)

无法通过约定推导的特殊路由，在 route_sync.go 中硬编码维护：

```
"POST:/api/system/roles/:roleId/permissions"  → system.role.assign_permissions
"PUT:/api/system/users/:id/password"          → system.user.reset_password
"POST:/api/cmdb/servers/:id/agent/deploy"     → cmdb.agents.deploy
"POST:/api/k8s/clusters/:id/test"             → k8s.cluster.connect
...
```

## 八、Casbin 模型配置 (casbin_model.conf)

```ini
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[role_definition]
g = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = g(r.sub, p.sub) && r.obj == p.obj && r.act == p.act
```

匹配逻辑：请求的角色(r.sub) 匹配策略角色(p.sub)，且权限码(r.obj) 匹配策略权限码(p.obj)，且操作(r.act) 匹配策略操作(p.act)。

## 九、权限分配运行时流程

```
管理页面分配权限给角色
  │
  ├── 1. 写入 sys_role_permissions 表
  │      INSERT (role_id, permission_id)
  │
  ├── 2. syncRoleToCasbin(role)
  │      ├── RemoveFilteredPolicy(0, role.Code)  — 删除该角色旧策略
  │      ├── GetRolePermissions(role.ID)          — 重新查询所有权限
  │      └── AddPolicy(role.Code, perm.Code, "*") — 写入 sys_casbin_rule
  │
  └── 生效：下次请求时 enforcer.Enforce 自动读取新策略
```

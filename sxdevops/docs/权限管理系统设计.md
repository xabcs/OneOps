# SxDevOps 权限管理系统设计文档

## 概述

SxDevOps 实现了一套完整的基于 RBAC（Role-Based Access Control）的权限管理系统，涵盖后端权限验证、前端权限控制和用户体验优化。本文档详细说明权限管理的设计理念和实现机制。

## 核心设计理念

### 权限模型架构

```
用户 (User) ←→ 角色 (Role) ←→ 权限 (Permission)
     ↑                           ↑
     └── 用户组 (UserGroup) ──────┘
```

**三层权限检查机制：**
1. **路由层**：页面级访问控制
2. **组件层**：按钮和功能显示控制  
3. **API层**：后端接口权限验证

### 权限编码规范

采用 `{模块}.{资源}.{操作}` 的命名规范：

- `rbac.user.manage` - 用户管理权限
- `ops.host.execute` - 主机执行权限
- `aiops.chat.view` - AIOps 查看权限
- `sqlaudit.order.submit` - SQL工单提交权限

**操作类型标准化：**
- `.view` - 查看权限
- `.manage` - 管理权限（增删改）
- `.execute` - 执行权限
- `.approve` - 审批权限
- `.submit` - 提交权限

### 权限验证机制

#### 核心权限检查函数

```python
def get_user_effective_permissions(user):
    """获取用户有效权限集合"""
    if not getattr(user, 'is_authenticated', False):
        return set()
    
    # 超级用户和演示账号拥有所有权限
    if getattr(user, 'is_superuser', False) or is_demo_account(user):
        return set(filter_feature_permissions(
            PermissionDefinition.objects.values_list('code', flat=True)
        ))
    
    # 获取用户直接角色权限
    direct_permissions = PermissionDefinition.objects.filter(
        roles__users=user
    ).values_list('code', flat=True)
    
    # 获取用户通过用户组间接获得的权限
    group_permissions = PermissionDefinition.objects.filter(
        roles__user_groups__users=user
    ).values_list('code', flat=True)
    
    return set(direct_permissions) | set(group_permissions)

def user_has_permissions(user, codes):
    """检查用户是否拥有指定权限"""
    codes = [code for code in (codes or []) if code]
    if not codes:
        return True
    if not getattr(user, 'is_authenticated', False):
        return False
    
    # 超级用户拥有所有权限
    if getattr(user, 'is_superuser', False) or is_demo_account(user):
        return True
    
    granted = get_user_effective_permissions(user)
    return all(code in granted for code in codes)
```

#### DRF 权限类

**RBACPermission 权限基类**
```python
class RBACPermission(BasePermission):
    message = '当前用户没有执行此操作的权限。'
    required_permissions = ()

    def has_permission(self, request, view):
        # 认证检查
        if not request.user or not request.user.is_authenticated:
            return False
        
        # 演示账号保护
        if is_demo_account(request.user) and request.method not in SAFE_METHODS:
            self.message = DEMO_ACCOUNT_MUTATION_MESSAGE
            return False
        
        # 权限检查
        codes = getattr(self, 'required_permissions', ()) or \
                view.get_required_permissions()
        if not codes:
            return True
            
        if user_has_permissions(request.user, codes):
            return True
            
        self.message = f'缺少权限: {", ".join(codes)}'
        return False
```

**RBACPermissionMixin 视图混入**
```python
class RBACPermissionMixin:
    permission_classes = [IsAuthenticated, RBACPermission]
    rbac_permissions = {}

    def get_required_permissions(self):
        mapping = getattr(self, 'rbac_permissions', {}) or {}
        action = getattr(self, 'action', None)
        codes = mapping.get(action, mapping.get('*', []))
        if isinstance(codes, str):
            return [codes]
        return list(codes or [])
```

## 前端权限实现

### 权限状态管理

**认证状态存储 (`stores/auth.js`)**
```javascript
export const useAuthStore = defineStore('auth', () => {
  const token = ref(localStorage.getItem('sxdevops_token') || '')
  const currentUser = ref(loadStoredUser())
  const permissions = computed(() => 
    currentUser.value?.effective_permissions || []
  )

  function hasPermission(code) {
    if (!code) return true
    if (currentUser.value?.is_superuser) return true
    return permissions.value.includes(code)
  }

  function hasAnyPermission(codes = []) {
    if (!codes.length) return true
    return codes.some(code => hasPermission(code))
  }

  return {
    token, currentUser, permissions,
    hasPermission, hasAnyPermission
  }
})
```

### 路由层权限控制

**路由守卫 (`router/index.js`)**
```javascript
router.beforeEach(async (to) => {
  const authStore = useAuthStore(pinia)
  
  // 初始化认证状态
  if (!authStore.initialized) {
    await authStore.bootstrap()
  }

  // 公开页面直接放行
  if (to.meta.public) {
    return true
  }

  // 未认证跳转登录
  if (!authStore.isAuthenticated) {
    return { name: 'Login', query: { redirect: to.fullPath } }
  }

  // 权限检查
  const allowed = to.meta.permission
    ? authStore.hasPermission(to.meta.permission)
    : authStore.hasAnyPermission(to.meta.anyPermissions || [])

  if (!allowed) {
    ElMessage.warning('你没有访问该页面的权限')
    return { name: 'Forbidden' }
  }

  return true
})
```

### API 层权限错误处理

**HTTP 拦截器 (`api/request.js`)**
```javascript
request.interceptors.response.use(
  (response) => response.data,
  async (error) => {
    const status = error.response?.status
    const msg = await extractErrorMessage(error)

    if (status === 401 && !isProfileRequest) {
      handleSessionExpired()  // 登录过期处理
    } else if (!(status === 401 && isProfileRequest) && !skipErrorMessage) {
      ElMessage.error(msg)  // 显示错误消息
    }

    return Promise.reject(error)
  }
)

function handleSessionExpired() {
  localStorage.removeItem('sxdevops_token')
  localStorage.removeItem('sxdevops_user')
  ElMessage.error('登录状态已过期，请重新登录')
  setTimeout(() => {
    redirectToLogin()
  }, 700)
}
```

### 菜单权限过滤

**侧边栏菜单动态过滤**
```javascript
const visibleMenuItems = computed(() => 
  menuItems
    .filter(isModuleVisible)  // 过滤模块可见性
    .map((item) => {
      if (!item.children) return item
      const children = visibleChildren(item.children)  // 过滤子菜单
      return { ...item, children }
    })
)

function checkMenuPermission(item) {
  if (item.permission) 
    return authStore.hasPermission(item.permission)
  if (item.anyPermissions) 
    return authStore.hasAnyPermission(item.anyPermissions)
  return true
}

function isModuleVisible(item) {
  if (item.hidden) return false
  if (!checkMenuPermission(item)) return false
  if (!item.children?.length) return true
  return visibleChildren(item.children).length > 0
}
```

## 权限处理流程

### 用户访问流程

```
1. 用户访问页面
   ↓
2. 路由守卫检查认证状态
   ↓ (未认证)
   跳转到登录页
   ↓ (已认证)
3. 检查路由权限配置
   ↓ (无权限)
   显示 403 页面
   ↓ (有权限)
4. 加载页面组件
   ↓
5. 组件内权限计算属性控制UI显示
   ↓
6. 用户操作触发 API 请求
   ↓
7. API 拦截器添加认证头
   ↓
8. 后端权限验证
   ↓ (无权限)
   返回 403，前端显示错误消息
   ↓ (有权限)
9. 执行业务逻辑
```

### 多层防护机制

| 层级 | 检查位置 | 检查方式 | 无权限处理 |
|------|----------|----------|------------|
| **路由层** | `router.beforeEach` | 检查路由 `meta` 权限配置 | 跳转 403 页面 |
| **菜单层** | `AppLayout.vue` | 过滤无权限菜单项 | 隐藏菜单 |
| **组件层** | Vue 组件计算属性 | 权限计算属性 | 隐藏按钮/功能 |
| **API层** | HTTP 拦截器 | 后端返回 403 状态码 | 显示错误提示 |
| **业务层** | 组件方法逻辑 | 二次权限检查 | 阻止操作执行 |

## 权限最佳实践

### 开发建议

1. **权限粒度控制**
   - 避免权限过于细分，增加管理复杂度
   - 采用功能模块 + 操作类型的两级权限编码

2. **权限检查位置**
   - 路由层：页面级访问控制
   - 组件层：UI 元素显示控制
   - API层：接口操作权限验证
   - 业务层：关键操作二次确认

3. **权限测试覆盖**
   - 测试每个角色的权限边界
   - 验证无权限时的错误处理
   - 确保权限检查不会被绕过

### 安全建议

1. **默认拒绝原则**
   - 默认情况下拒绝所有访问
   - 明确授予所需权限
   - 定期审查用户权限

2. **权限最小化原则**
   - 仅授予用户完成工作所需的最小权限
   - 优先使用角色而非直接授权
   - 及时回收离职人员权限

3. **审计和监控**
   - 记录所有权限变更操作
   - 监控异常权限使用情况
   - 定期审查用户权限分配

### 性能优化

1. **权限缓存**
   - 前端缓存用户权限信息
   - 避免重复权限查询
   - 权限变更时主动刷新

2. **权限预加载**
   - 登录时预加载用户权限
   - 初始化时检查路由权限
   - 减少运行时权限检查开销

## 总结

SxDevOps 的权限管理系统具有以下特点：

1. **架构完整**：从前端到后端的多层权限防护
2. **易于扩展**：基于 RBAC 的灵活权限模型
3. **用户友好**：无权限时的友好提示和处理
4. **安全可靠**：严格的权限验证和审计机制
5. **维护便捷**：集中化的权限定义和管理

通过这套权限系统，确保了平台的安全性和可管理性，为不同角色的用户提供了合适的访问控制。

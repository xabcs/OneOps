# OneOps 后端目录结构总结

## 项目概述

OneOps 是一个全栈运维管理平台，后端采用 **Go 语言** 开发，基于 **Gin Web 框架**，使用 **GORM** 进行数据库操作，**Casbin** 进行权限管理。

### 核心技术栈
- **语言**: Go 1.23+
- **Web 框架**: Gin (https://gin-gonic.com/)
- **ORM**: GORM (https://gorm.io/)
- **权限管理**: Casbin (https://casbin.org/)
- **数据库**: MySQL
- **缓存**: Redis
- **日志**: Zap (https://github.com/uber-go/zap)

## 架构设计模式

### 1. 分层架构
```
┌─────────────┐
│  HTTP 请求  │
└──────┬──────┘
       │
┌──────▼──────┐
│  中间件层   │ ← 认证、权限、日志、错误处理
└──────┬──────┘
       │
┌──────▼──────┐
│  控制器层   │ ← 处理 HTTP 请求
└──────┬──────┘
       │
┌──────▼──────┐
│  服务层     │ ← 业务逻辑、数据库操作
└──────┬──────┘
       │
┌──────▼──────┐
│  数据模型层 │ ← GORM 模型、数据库表定义
└──────┬──────┘
       │
┌──────▼──────┐
│   数据库    │ ← MySQL/Redis
└─────────────┘
```

### 2. 依赖注入
使用 `container` 包实现单例模式的管理：
- 所有服务实例统一管理
- 避免循环依赖
- 方便单元测试

### 3. 中间件链
Gin 中间件按以下顺序执行：
1. **CORS** - 跨域处理
2. **Logger** - 请求日志
3. **Recovery** - Panic 恢复
4. **Auth** - JWT 认证
5. **Permission** - Casbin 权限检查
6. **Audit** - 操作审计

## 总结

OneOps 后端采用标准的 **Go 分层架构**，代码组织清晰，职责分明：

### 架构优势
- ✅ **分层清晰**: Controller → Service → Model
- ✅ **依赖注入**: 统一管理服务实例
- ✅ **中间件丰富**: 认证、权限、日志、审计全覆盖
- ✅ **安全性高**: JWT + Casbin + 数据加密
- ✅ **可扩展**: 模块化设计，易于添加新功能
- ✅ **可维护**: 代码规范统一，遵循 Golang 最佳实践

### 核心能力
1. **CMDB 资产管理**: 服务器全生命周期管理
2. **K8s 集群管理**: Kubernetes 资源操作
3. **监控告警**: 实时监控和告警规则
4. **权限控制**: 细粒度的 RBAC 权限
5. **审计追踪**: 全链路操作审计
6. **堡垒机**: 安全的 SSH/Web 终端

这是一个设计良好、功能完善的企业级运维管理平台后端系统。

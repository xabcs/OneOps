# Golang 命名规范改造计划

## 当前问题分析

根据 `/Users/mpm/Desktop/doc/go/OneOpsV2/OneOps/backend/docs/golang命名规范.txt`，发现以下不符合规范的地方：

### 1. 目录命名问题

| 当前名称 | 问题 | 建议名称 | 原因 |
|---------|------|---------|------|
| `middlewares` | 复数形式 | `middleware` | Go 约定使用单数形式 |
| `controllers` | 复数形式 | `controller` | Go 约定使用单数形式 |
| `handlers` | 复数形式 | `handler` | Go 约定使用单数形式 |
| `utils` | 太通用 | 拆分为具体功能包 | 避免 util、common 等通用名称 |
| `dto` | 不够描述性 | `request` 或 `dto` | 需要更具描述性 |

### 2. 包导入路径影响

重命名目录会影响所有导入这些包的文件，需要同步修改：
- 所有 `import` 语句
- 所有包声明
- 配置文件引用（如有）

## 改造方案

### 阶段一：目录重命名

1. **middlewares → middleware**
   - 影响文件：所有导入 `oneops/backend/middlewares` 的文件
   - 修改量：约 5-10 个文件

2. **controllers → controller**
   - 影响文件：所有导入 `oneops/backend/controllers` 的文件
   - 修改量：约 10-15 个文件

3. **handlers → handler**
   - 影响文件：所有导入 `oneops/backend/handlers` 的文件
   - 修改量：约 5-10 个文件

### 阶段二：包重命名（可选）

**utils 包拆分方案**：
- `utils/encryption.go` → `crypto/encryption.go`
- `utils/jwt.go` → `auth/jwt.go`
- `utils/password.go` → `auth/password.go`
- `utils/response.go` → `http/response.go`
- `utils/pagination.go` → `http/pagination.go`
- `utils/validation.go` → `validator/validation.go`

**注意**：utils 拆分工作量较大，建议后续单独进行。

## 风险评估

- **风险等级**：中等
- **影响范围**：所有后端代码
- **回滚策略**：使用 Git 分支管理，可随时回滚
- **测试要求**：改造后需运行完整测试套件

## 建议

1. **优先级**：先处理 controllers/middlewares/handlers 的复数形式问题
2. **utils 包**：建议后期单独重构，当前影响面太大
3. **测试覆盖**：改造前确保有足够的测试覆盖
